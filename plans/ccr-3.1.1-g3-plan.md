## 1. ARCHITECTURE

### 1.1 One process owns everything

`harness/trial31/g3/g3-run.mjs` is the ONLY long-lived process. It starts the sandbox daemon(s) as non-detached, non-unref'd children (stdio to `run\daemon.*.log`), starts the stubs in-process, drives all measurements, and tears everything down. Rationale: at G2 the PowerShell tool reaped the daemon ~60 s after `start31` returned (it had been `unref`'d, start31.mjs:211). A daemon whose owner is a live orchestrator that lives inside ONE background tool call is the only supported shape.

Invocation (never inherits `NODE_OPTIONS`; the airgap is a CLI `--require`):
`node --require harness/trial31/preload-net31.cjs harness/trial31/g3/g3-run.mjs --g3-approved [--phase <ids>] [--dry] [--resume] [--arms v311[,ctlP,ctlS]]`
Run via `run_in_background` (Bash or PowerShell tool) with a Monitor on the stdout event lines, or, guaranteed fallback, by the user pasting the one command into their own terminal (the orchestrator has no tool dependencies). The orchestrator prints one line per event and a heartbeat every 30 s.

Liveness question is settled EMPIRICALLY before G3a, not assumed: stage **S0** runs `g3-run.mjs --liveness-soak 8` (no CCR: a guarded idle node child and one stub, polled 8 minutes). If the child dies before 8 min under the chosen tool, try the next launcher in this order: Bash `run_in_background`, PowerShell `run_in_background`, user terminal.

Single-instance lock: `TRIAL_ROOT\run\g3.lock` created with `wx` (pid + start time); a second orchestrator refuses.

### 1.6 Stub design (`stubs.mjs`; every stub records, none forwards anywhere but loopback)

One `http.Server` per port; keep-alive on; `listenLoopback(server, port)` asserts `port in PORTS.stubs` before `listen(port,"127.0.0.1")`.
- **Routing/identity**: path `/pNN/v1/messages` (Anthropic) or `/pNN/v1/chat/completions` (OpenAI, also accept `/pNN/chat/completions`). `POST /__ctl/register {id, keyHash}` (the expected credential hash for that provider), `POST /__ctl/mode {id, mode, params}`, `GET /__ctl/hits`, `POST /__ctl/reset`. `/__ctl/*` accepts only `Host: 127.0.0.1:<port>` and no `Origin`.
- **Capture** per request: `{t, provider, path, method, headers (lower-cased names; credential-bearing values replaced by `sha256:` + first 12 hex + length), credOk (hash equals the registered one), bodyBytes, bodySha256, body (string, capped 256 KB), arrivalHr}`. Ring buffer of 2,000; per-provider hit counter.
- **Modes** (per provider, switchable at runtime): `ok` (instant), `latency:<ms>`, `json` / `sse` (stream: `message_start` -> `ping`x n at a set interval -> `content_block_start` -> `content_block_delta` -> `content_block_stop` -> an **unknown event type** `x_uw_unknown_event` with a data object -> `message_delta` -> `message_stop`; OpenAI variant emits `data:` chunks + `[DONE]`), `sse_truncated` (socket destroyed after N events, no `message_stop`), `status:<code>` with an Anthropic-shaped JSON error `{type:"error",error:{type,message:"uwtrial-reason-<rand>"}}` (401/429/500/503), `close` (socket destroyed before headers), `hang` (never answers), `safeguards` (response carries `safeguard_results` in the JSON body and in the streaming `message_delta`, plus an unknown top-level field, plus `message_start.message.model` = a value different from the requested model).
- **Anthropic reply body** is a fixed, hand-serialised text (not re-`stringify`d) so byte-level differences introduced by CCR (key order, number/escape formatting, `\u2028`) are detectable by raw compare, then parsed deep-equal.
- **Relay stub (39485)** = faithful reimplementation of F15 (loopback-literal Host check, Origin/Referer 403, JSON parse, identity prepend, `JSON.stringify`, exactly 5 forwarded headers with `mergeBetas`, verbatim status/header/body pipe) forwarding over plain http to 39480 `/p-relay-up/v1/messages`. **Drift guard**: a test READS the real relay source (read-only) and asserts the stub's exported constants (`IDENTITY_TEXT`, `OAUTH_BETA`, the 5-header list, `mergeBetas` output on 5 vectors) equal the ones parsed from the source text; the real relay is never imported or run (it needs the OAuth credential and hard-codes `api.anthropic.com`).
- **Direct baseline** (M1): the orchestrator sends the same body with the same client to the stub directly; the difference isolates CCR.

## 2. MEASUREMENTS

Common method. Client = `node:http` with a keep-alive agent (same client for direct and via-CCR), `process.hrtime.bigint()`, non-streaming small reply unless stated. Blocks of 10 requests; arm order per cell is a Latin square over arms (v311, ctlP, ctlS) so drift hits arms equally. Per cell: 5 warm-ups (discarded, recorded), 30 timed. Reported: n, median, nearest-rank p95 (the 29th of 30), min, max, MAD-based outlier count (>3 MAD, kept, flagged), 95% bootstrap CI of the median (2,000 resamples, fixed seed 20260930). A cell is INVALID (rerun once, then reported invalid) if: any non-2xx, any misroute, CPU busy from other processes > 50% in any block (sampled with `os.cpus()` deltas before/after each block), `refresh\state\bench.lock` exists (read-only stat; resolve the path from `LOCK_FILE` in refresh/bench-lock.mjs), or the poller reported a trip. Adaptive n: if the 5 warm-ups have median > 2 s, timed n drops to 15 for that cell and the report says "n=15". Timed blocks are never overlapped with poller spawns (H8 pause/resume).

### 4.2 Abort conditions (any one: stop load, run the cleanup stack, classify, do NOT widen the guard inside the same run)

1. `violations.log` non-empty (tail-polled every 2 s and at every block edge). A first-ever violation at G3 is EXPECTED to be possible (the core child, the request-log worker and the gateway have never run under the guard); it is reported with the redacted line and the nearest allowlist template, and the fix is a reviewed change plus a fresh run.
2. Tripwire trip (poller exit 3 or a block-edge assert), including a blind collector (H3).
3. Any listener owned by the daemon tree outside {39466,39467,39468}; any non-loopback established connection in the tree; live ports 3456/3457/3458/4517 changing owner pid or process start time; 39484 becoming occupied.
4. Daemon or core child exit not requested by the orchestrator; gateway not `running` within 30 s of a save; RPC 5xx twice in a row.
5. Time budget: hard cap 150 min total (soft: S1 5, S2-S3 25, S4 40 (3.1.1 grid ~10 min; M2/M2c ~8 min; M3/M9 ~5 min; padded for G3b controls +40), S5 5, S6 5, teardown 5). Disk budget: growth of `TRIAL_ROOT` > 1 GB (request-log bodies of 80 KB x ~1,300 requests is ~100 MB, DB and logs small) or free space on `C:` < 5 GB, checked every block.
6. `results\STOP` file exists (polled every 1 s) = cooperative abort; `refresh\state\bench.lock` appearing mid-run = cell invalid + pause until gone (max 10 min, else abort).
7. Guard/harness self-check failure at any time (canary flag lost, `guard-loaded.log` missing a node.exe of the tree, H8 poller not alive).

### 4.3 Cleanup guarantees in ONE process

A LIFO cleanup stack, idempotent and re-entrant, run on: normal end, `SIGINT/SIGTERM/SIGBREAK/SIGHUP`, `uncaughtException`, `unhandledRejection`, every abort condition. Steps: (1) stop client traffic, (2) stop the poller (after one last assert), (3) close stubs, (4) stop every daemon by HANDLE with the existing identity-verified `stopOwnedChild`/`stopVerified` (never a bare pid kill), (5) `autoClean` (PATH restore only of sandbox segments, sandbox delete keeping install + evidence + results), (6) final tripwire assert + section 4.4 checks, (7) `runTeardown` semantics for the kit. What it CANNOT do: run anything after a forced kill of the orchestrator (TerminateProcess). Backstops for that: the H11 heartbeat kills daemon and core child within ~60 s, the restore kit and evidence logs are never auto-deleted on failure, and the recovery command is `node harness/trial31/teardown31.mjs` (then `--discard-kit` only when the process table shows no sandbox daemon).

### 4.4 Verified BEFORE and AFTER (recorded in `results\g3-results.jsonl`, compared by equality, fingerprints only, never contents)

real ports 3456/3457/3458/4517: owner pid AND process start time (read-only CIM; no traffic); HKCU user PATH raw value+type hash and Internet Settings + user Root store fingerprints (tripwire31.mjs:90-104); real `~\.claude\settings.json` sha256 AND marker-line count (today 2), `settings.local.json`, `.codex\config.toml`, `.codex` top listing, `.claude` sidecar names and `.claude.json` presence (H5); real Claude-3p: `claude_desktop_config.json`, `configLibrary\_meta.json`, `configLibrary\<id>.json` hashes and the `configLibrary` listing (tripwire31.mjs:123-131); real CCR dir: `service.json`, `global-profile-takeover.json` hashes and the `bin` listing; `config.sqlite` and `usage.sqlite` mtime+size of the real CCR dir are RECORDED as informational only (the live gateway and other agents legitimately move them, so they are not a tripwire); `~\Downloads` listing; `node keysync/ccr-patch.mjs --check` output unchanged (5 of 5, `cli.js` sha `160bf3ff4142b76b`); live gateway "untouched" = same listener pid + start time on 3456/3457 and no connection from the sandbox (guard + zero non-loopback rows). The isolation proof (`verifyIsolation`) re-runs at G3 start and again at the end.

### 4.5 How a violation is reported

One line to stdout and to `results` immediately: `VIOLATION <kind> phase=<id> cell=<id> :: <redacted message up to 600 chars> :: nearest-template=<id>`; the orchestrator does NOT retry the call and does NOT edit any allowlist. Exit code 1 (violation) / 3 (tripwire) / 4 (budget) / 5 (daemon died) / 2 (refused: not approved or preflight). The restore kit is kept on any non-zero exit.

### 4.6 Data hygiene

Fake keys are runtime `uwtrial-fake-<hex>` values held in memory and stored by CCR inside the owner-only sandbox only; no key or token is ever printed, written to results, or placed in a repo file; the stub stores hashes of credentials, never values; request bodies are stored as sha256 + size + selected fields (M12 keeps only the `safeguards` subtree); `service.json` content is never read out by the orchestrator except for `pid` and the URL port; `daemon.*.log` only through the redactor (H9/H10); no test file contains a secret-shaped literal (build any sample from split pieces at runtime, cf. memory "fake secrets in tests").
